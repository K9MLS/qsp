Bring other radios in with DVSwitch

DVSwitch is free software that turns audio from one kind of radio system into another. Run on your own machine, it lets an AllStar repeater or node take part in this network — and the people on it keep the radios they already have.

What it gets you

  • AllStar to DMR

    Anyone on your AllStar node, on any FM radio, talks on one of this network's DMR talkgroups, and DMR users hear them.

    You set it up Published

  • AllStar to P25

    The same, on this network's P25 side. QSP copies P25 as it comes, so the node is heard by every P25 hotspot and repeater linked here.

    You set it up Published

  • YSF, D-STAR or NXDN onto DMR

    A DVSwitch machine with a vocoder joins a reflector of another mode to one DMR talkgroup here.

    The network's administrator Published

  • DMR and P25 as one conversation

    A DVSwitch machine converts between a DMR talkgroup and a P25 one on this network, so users of both hear each other.

What you need

  • DVSwitch on the machine beside your node: a Raspberry Pi or any Debian computer. The DVSwitch Server package installs MMDVM_Bridge, Analog_Bridge and the gateways together.
  • A vocoder for DMR: a ThumbDV or DV3000 on USB, or the software one DVSwitch offers on some machines. It does the converting, on your hardware; this server converts nothing for you.
  • Your DMR ID, and the network’s password from whoever runs it. P25 uses the same ID.

This network admits only stations it has listed. Send your node’s DMR ID to whoever runs it first, or it will be turned away however right the rest is.

DVSwitch Server’s dvs menu sets most of what follows for you. The file names below are the ones it writes, usually under /opt; check them against your install.

Setting up AllStar to DMR

MMDVM_Bridge logs in here as a hotspot does, so its values are a hotspot’s.

In MMDVM_Bridge.ini

[General] Id Your DMR ID
[DMR Network] Enable 1
[DMR Network] Address …
[DMR Network] Port …
[DMR Network] Password Sent to you separately — it is not shown on this page

In Analog_Bridge.ini, under [AMBE_AUDIO]

ambeMode DMR
gatewayDmrId The same DMR ID; your node’s calls carry it
txTg A talkgroup from the table below
txTs Its timeslot
This network’s talkgroups
txTg txTs Name
Loading…

One talkgroup at a time. Changing it from the node by DTMF is a DVSwitch feature Not known here.

Setting up AllStar to P25

This network is not taking P25 gateways right now. Ask whoever runs it; the settings appear here when it is.

The same machine, switched to P25. Its P25Gateway reaches this server as a P25 hotspot’s does, and needs no vocoder of yours for P25 to P25.

In Analog_Bridge.ini, under [AMBE_AUDIO]

ambeMode P25
txTg The reflector number whoever runs this network gives you

In MMDVM_Bridge.ini

[P25 Network] Enable 1

In P25Gateway.ini

[General] Callsign Your callsign. Ask for it to be added to the P25 gateways this network answers
[Network] Startup The same reflector number

And one line in P25Gateway’s local hosts file, with that number first

number  …  …

If the number is already in the downloaded host list, that entry wins and yours is ignored: check both. Restart P25Gateway after any change, then relink. Whether DVSwitch’s P25 audio needs a vocoder of its own is Not known here.

For the network’s administrator

Other modes onto DMR. A DVSwitch machine with a vocoder logs in here as a hotspot on one talkgroup, and to a YSF, D-STAR or NXDN reflector on the other side, converting between them.

DMR and P25 together. The same machine on both of this network’s sides: a hotspot on a DMR talkgroup and a P25 gateway on a reflector number, converting AMBE to IMBE and back.

QSP itself converts nothing between modes, by design: a vocoder in the server would be one shared channel deciding who is heard. Each machine that converts brings its own, and the server carries what arrives.

When it does not work

You see Look at
Nothing reaches the network The address and port above, and whether your machine can reach them over UDP
The node connects, and its calls never appear txTg and txTs, then gatewayDmrId
Refused, or connected and then dropped Your DMR ID, password or callsign, with whoever runs the network
Too loud or too quiet one way Analog_Bridge’s gain settings, on your machine. Nothing here changes your audio
