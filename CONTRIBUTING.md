# Contributing to QSP

Thank you for considering it. This document is short; the rules in it are
load-bearing.

## Before you write code

Read [`ARCHITECTURE.md`](ARCHITECTURE.md), particularly §2 (Invariants) and §3
(Dependency rules). A change that breaks an invariant is a redesign, not a
refactor, and needs an ADR.

## The rules that matter most

### 1. Never fake anything

QSP must never contain fake protocol handlers, mock behaviour presented as
production behaviour, hardcoded metrics, sample peers, sample traffic, or
seeded demo data.

**If something is not implemented, the application says so.** That is why
`health.StatusUnavailable` exists and why the console renders honest empty
states. An operator must always be able to trust that what they are looking at
is real.

This extends to screenshots. Screenshots come from a running system with real
data, never from seeded content.

### 2. Never guess at a protocol

Do not invent packet formats, state machines, timing behaviour or protocol
semantics. Protocol code is written against authoritative specifications,
captured real traffic, or verified interoperability behaviour.

If you are uncertain, stop and say so in an issue. An honest "I don't know"
costs an afternoon; a confident guess costs somebody's repeater.

See [ADR-0008](docs/adr/ADR-0008-protocol-licensing.md) — protocol work is
currently blocked on an unresolved licensing question.

### 3. Nothing incomplete

No TODOs, no FIXMEs, no empty production functions, no commented-out
implementations, no "coming soon" paths, no unused abstractions built ahead of
their requirements.

A change is complete or it is not merged.

### 4. Tests are part of the implementation

Not a follow-up. Every feature arrives with its tests.

Prefer **named failure-mode tests** over coverage percentages.
`TestReplayReportsIncompleteWhenHistoryEvicted` tells the next reader what
property is being protected; 84% coverage tells them nothing.

Where an external reference implementation exists, verify against it. The
PBKDF2 code is tested against vectors generated by OpenSSL, not against itself.

### 5. Errors explain how to fix themselves

Never merely report that a value is invalid.

```go
// No
return errors.New("invalid level")

// Yes
return fmt.Errorf("unknown log level %q: valid values are \"debug\", \"info\", \"warn\" and \"error\"", s)
```

This is enforced by test for configuration validation.

### 6. Never log a secret

Use `logging.Redacted` when a credential's presence is meaningful but its value
is not. `audit.Redact` matches key names deliberately over-eagerly; a needless
redaction costs nothing and a leak is unrecoverable.

## Adding a dependency

The core binary currently has none ([ADR-0004](docs/adr/ADR-0004-no-external-dependencies.md)).
That is a default, not a vow. To add one, open an issue documenting:

- why the standard library is insufficient
- licence, and its compatibility with GPL-3.0
- maintenance status and release cadence
- security history
- whether it introduces cgo — which is disqualifying for the core

## Before you open a pull request

```sh
gofmt -l .          # must print nothing
go build ./...
go vet ./...
go test ./...
go test -race ./...
```

All must pass. `-race` is not optional; it has already caught one real defect
here.

## Commits

Small and logical, one coherent change each.

```
chore: initialize Go module
feat: add HBP packet parser
test: add HBP golden frame fixtures
fix: serialise event delivery against subscription closure
docs: record the schema downgrade decision
```

Never commit secrets. Never commit generated binaries.

## Code review

Reviewers ask:

- Does it break an invariant?
- Is anything faked, stubbed or guessed?
- Are the failure paths handled *and tested*?
- Do the errors tell an operator how to fix them?
- Could a hostile packet reach this code, and what happens if it does?
- Is there an abstraction here that no requirement has asked for yet?

## Conduct

Be decent. This is a hobby project for amateur radio operators; nobody is paid
to be here, including you.

## Addresses

**No public IP address goes in this repository**, in code, tests, documents or
captures. Use a documentation range — `203.0.113.x`, `198.51.100.x`,
`192.0.2.x` — or a private one where that is what is meant. A test refuses
anything else, including addresses that are public infrastructure: a reflector,
a DMR master, a resolver in an example. That rule exists because judging each
address on its merits is exactly how another operator's home address ended up
in ten files, four of them Go tests written from a real capture.

**Captures carry more than the address.** Take them with a capture filter, or
run `scripts/filter-capture.py` before committing: three captures here held
mDNS, Syncthing and SSDP traffic from a home network, naming devices and
services. Two tests in `internal/p25link` refuse a capture with traffic that is
not radio, or with a device identity inside it.
