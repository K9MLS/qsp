# ADR-0006: PBKDF2-HMAC-SHA256 with a self-describing hash format

**Status:** Accepted

## Context

Argon2id is the current recommendation for password hashing. It lives in
`golang.org/x/crypto`, which was unreachable when this foundation was built
(ADR-0004), and adding it later must not invalidate existing passwords.

The standard library provides HMAC and SHA-256 but not PBKDF2.

## Decision

PBKDF2-HMAC-SHA256 per RFC 8018, implemented over `crypto/hmac`. 600,000
iterations, 16-byte random salt, 32-byte key.

Hashes are stored self-describing:

```
$pbkdf2-sha256$i=600000$<base64 salt>$<base64 key>
```

`NeedsRehash` reports when a stored hash is below current policy. The
application rehashes on the next successful login.

## Consequences

- No dependency, and the algorithm is well specified rather than invented.
- **Verified against an external reference.** The implementation is tested
  against six known-answer vectors generated by CPython's OpenSSL-backed
  `hashlib.pbkdf2_hmac`, including multi-block output and embedded NUL bytes.
  Testing a cryptographic primitive only against itself proves nothing.
- **PBKDF2 is weaker than Argon2id against GPU attack.** Accepted knowingly. The
  self-describing format is the mitigation: migrating to Argon2id means adding
  the algorithm, raising the policy, and letting `NeedsRehash` upgrade users on
  login. Nobody is locked out.
- Work per verification attempt is bounded by `MaxPasswordLength`, so an
  unauthenticated caller cannot force arbitrary CPU consumption.
- Password policy enforces **length only**. Composition rules push people toward
  predictable substitutions and away from length, which is what actually resists
  offline attack.
